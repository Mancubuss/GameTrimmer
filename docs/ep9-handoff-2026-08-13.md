## Decisions already made — do not re-litigate

**Container:** `.zip`, Deflate level 6, no user-facing level setting. Measured on
the real release database (1 598 games, 4 924 011 files, 720 165 findings):
default bundle 83 KB, 5 000 findings 191 KB, 50 000 findings 1.29 MB, every
finding 16.0 MB. Solid archiving gains 0.01 %. 7z and zstd win 20–25 % and lose
on both counts that matter — Explorer opens Deflate zips and nothing else
without extra software, and `zip` + `flate2` are the only codecs already
resolvable in the tree.

**Opt-in detail cap:** 50 000 rows, with `"truncated": true, "total_rows": N,
"included_rows": M` declared in the payload. No unbounded mode.

**Bundle layout:** `manifest.json`, `summary.txt`, `settings.json`,
`rules.json`, `db_health.json`, `scan_runs.json`, `games.json`, `findings.json`,
`operations_summary.json`, `operations_detail.json` (opt-in), `errors.txt`.
Excluded sections are **absent files, not empty ones**.

**Manifest fields:** `schema_version`, `generated_at` (UTC), `generation_id`
(per-generation UUID, never a stable install id), `app_version`,
`sections_included`, `redaction_applied: true`.

**Version policy:** bump only on a breaking field change. A reader meeting an
unknown newer version refuses to interpret unrecognized structured fields but
never refuses to show `summary.txt` — the same rule `db.rs:217` already applies
to a newer database.

**No checksum.** Zip's own CRC32 covers copy corruption and there is no
automated receiving pipeline that would need more.

**Privacy defaults:** paths tokenized `<LIBRARY_n>` always; account name redacted
always via one shared pass applied to every text field *after* serialization,
matched against the live `%USERPROFILE%`; machine GUID and volume serials never;
game titles opt-in and slot-tokenized even then; content hashes opt-in; operation
journal aggregates always, row detail opt-in.

**Placement:** Settings → "Дані та діагностика", beside the database path. Not a
new panel.

**Dependencies:** add `zip` 8.6.0. Promote `flate2`, `crc32fast`, `uuid`,
`chrono` from transitive to direct. Do not add `sha2`/`blake3`.

**Transport:** none, at any point in this work. The app never uploads. Delivery
is the user attaching the file themselves.

## Traps worth knowing before touching the code

- **`atomic_file::atomic_write_with_backup` takes a complete `&[u8]`.** Build the
  whole zip in memory via `ZipWriter<Cursor<Vec<u8>>>` first, then one call. Do
  not write a new incremental variant — the existing guarantee is what makes a
  cancelled run leave no plausible partial file.
- **Redaction must run last, after serialization, over free text.**
  `rusqlite::Error` and `std::io::Error` embed full paths through `Display`, so
  field-level redaction alone leaks the account name through error strings.
- **Steam and Epic manifests carry account identifiers** the providers see in
  passing. The bundle must carry only what the provider *derived* — library path,
  game name, app/build id, already columns in `games` — never the manifest's own
  account fields. That is a narrowing of the projection, not a redaction pass.
- **Never iterate `env::vars()`.** Name any variable that is diagnostically
  useful and redact its value.
- **`FindingRow::group_dir`'s doc is wrong** (`model.rs:99-102` says it is never
  persisted; `persistence.rs:377` writes it and `load.rs:272` reads it). Fix it
  while assembling the field list — it is listed inside GT-121.
- **Test modules share files with production code** in `scan.rs`, `model.rs`,
  `db.rs` — all over 2 000 lines. Read them in chunks.
- **`cargo tree` on this tree is currently clean** of any HTTP/TLS/async crate.
  That is the state GT-122 exists to freeze; check it before and after any
  dependency change.
