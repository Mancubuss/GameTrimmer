## Мета

Користувач хоче, щоб спільнота могла доповнювати правила аналізу без
перекомпіляції: одна бібліотека ігор не покриває всі конвенції
(приклад-межа: EU4 `province_names\*.txt` лікується лише пер-ігровим
правилом). Алгоритми (сім'ї, позиційний аналіз) лишаються в коді;
спільнота розширює ДАНІ.

## Архітектура

Два файли поруч із застосунком. Обидва МАТЕРІАЛІЗУЮТЬСЯ з вбудованих
даних при першому зверненні (`worker::ensure_rules_path` /
`ensure_l10n_rules_path`) і читаються сканером ВИКЛЮЧНО з диска — жодних
невидимих вбудованих правил і жодного fallback на корінь репозиторію:
користувач завжди бачить у файлах рівно те, що виконується. Вбудоване
«насіння»: `rules::BUILTIN_RULES_JSON` (include_str! репозиторного
rules.json на момент збірки) та `LangPack::builtin()`. Наявний файл
ніколи не перезаписується мовчки — правки користувача та імпортовані
пакети завжди мають пріоритет; збій створення/читання/парсингу дає
warning і разовий відкат на вбудовані таблиці, не зриваючи сканування.

1. `rules.json` — масив правил категорій (формат не змінюємо, щоб не
   ламати сумісність).
2. `l10n_rules.json` — дані мовного детектора:

```json
{
  "version": 1,
  "languages": [
    {"key": "fr", "level_a": ["french", ...], "level_b": ["fra","fre"], "level_c": ["fr"]}
  ],
  "industry_words": ["schinese", ...],
  "keep_default": ["uk", "en"],
  "markers": {
    "negative": [...],
    "overridable_negative": ["textures", "gui"],
    "audio": [...], "text": [...], "video": [...], "font": [...],
    "loc_generic": [...], "loc_specific": [...],
    "video_extensions": [...], "font_extensions": [...], "text_extensions": [...]
  }
}
```

## План імплементації

1. **`LangData` struct** у `langdetect`: усі таблиці, що зараз const/static
   у `dict.rs` і `markers.rs`. Побудова: `LangData::builtin()` (з
   нинішніх const) та `LangData::from_json(&str)`.
   - `Occurrence.canonical`/`FamilyHit.canonical` — `&'static str`:
     для завантажених пакетів інтернувати рядки (Box::leak через
     глобальний OnceLock-інтернер), щоб не міняти типи по всьому коду.
2. **Прокинути `&LangData`** через `LangDetector` → `collect_occurrences`,
   `scan_markers`, `family::compute_*` (замість прямих звернень до const).
   `dict::lookup(text)` → метод `LangData::lookup`.
3. **Завантаження**: worker/scan.rs — поруч із RuleEngine::load; файл
   відсутній → builtin (не помилка). Невалідний JSON → повідомлення
   користувачу (send_warning), fallback на builtin.
4. **Тести**: builtin == поведінка до рефакторингу (report_cases +
   corpus мають лишитися зеленими без змін); from_json роунд-тріп;
   кастомний пакет перевизначає (нова мова + новий негативний маркер).
5. **Експорт/імпорт UI** (settings_dialog.rs):
   - «Експортувати правила» → зберегти rules.json + l10n_rules.json
     (поточні ефективні) у вибрану теку (rfd file dialog вже в проєкті?
     перевірити).
   - «Імпортувати правила» → вибрати файл(и), злиття: правила категорій —
     за (category, pattern) (нові додаються, збіги замінюються);
     мови — за canonical key (об'єднання аліасів); маркери — об'єднання
     множин. Записати в файли поруч із exe. Перед злиттям — бекап
     `*.bak`.
6. **Версійність**: поле `version`; при невідомій мажорній версії —
   попередження і builtin.
