## 1. Головне резюме (Executive Summary)

Сучасні ігри та лаунчери накопичують десятки гігабайтів баласту поза основними директоріями інсталяцій або у специфічних структурах, які традиційні утиліти очищення (CCleaner, BleachBit, Disk Cleanup) або **не помічають**, або **видаляють деструктивно**, руйнуючи цілісність авторизацій, кешів та збережень.

## 3. Деталізація завдань епіку

### 3.1. GT-181: [Спайк] Воркшоп та незавершені завантаження Steam/EGS
- **Проблема:** Steam часто залишає тимчасові депоти в `steamapps/downloading` при скасуванні/помилках завантажень, а штатна кнопка "Очистити кеш завантаження" вибиває користувача з акаунту й скидає 2FA. Моди у `steamapps/workshop/content` залишаються після відписки від них на сайті або видалення гри.
- **Рішення:** 
  1. Парсинг `appworkshop_<appid>.acf` через KeyValues для отримання переліку підписок `WorkshopItemDetails`. Папки з ID поза підписками або деінстальованих ігор — маркуються як `Category::WorkshopOrphan`.
  2. Перевірка `appmanifest_<appid>.acf` та відсутності дескрипторних блокувань для очищення `steamapps/downloading` без розлогінювання.

### 3.2. GT-182: [Спайк] Шейдерні кеші GPU та Steam Pipeline Cache
- **Проблема:** Драйвери NVIDIA (`%LOCALAPPDATA%\NVIDIA\DXCache`) та AMD (`DxCache`) накопичують гігабайти шейдерів. При оновленні драйвера старі бінарники стають мертвими, але не видаляються. Стандартний Windows Disk Cleanup бездумно стирає все підряд, викликаючи мікрофризи у всіх активних іграх.
- **Рішення:** 
  1. Детекція застарілих версій драйвера в заголовках кешу.
  2. Видалення застарілих файлів за критерієм останнього доступу (mtime > 30-60 днів).
  3. Очищення `steamapps/shadercache/<appid>` для деінстальованих AppID.

### 3.3. GT-183: [Спайк] Дампи падінь та логи ігрових рушіїв
- **Проблема:** Unreal Engine 4/5 генерує важкі Minidumps та зліпки пам'яті (`Saved/Crashes`, `Saved/Logs`). Unity створює `Player.log`, який при зацикленні може сягати десятків гігабайтів. Windows WER збирає `.dmp` у `CrashDumps`.
- **Рішення:** 
  1. Категорія правил `Category::CrashDump` та `Category::DiagnosticLogs`.
  2. Безпечне фонове очищення після закриття гри (100% безпечно, рушії ніколи не читають старі дампи).

### 3.4. GT-184: [Спайк] Проріджування автосейвів (Smart Save Retention)
- **Проблема:** RPG (Skyrim з 998 сейвами на 1.8 GB, BG3, Starfield, OpenMW, Cyberpunk) генерують сотні проміжних квіксейвів. Це призводить до розростання папки на 5–50 GB та зависання синхронізації Steam Cloud.
- **Рішення:** 
  1. Відокремлення ручних іменованих сейвів (`ManualSave`) від автосейвів (`QuickSave`, `AutoSave`).
  2. Алгоритм Smart Retention: збереження $N$ найновіших квіксейвів на персонажа/кампанію.
  3. Обов'язкове попереднє пакування в ZIP-бекап перед будь-якою операцією видалення (Zero-Data-Loss Shield).

### 3.5. GT-185: [Спайк] Мод-менеджери та веб-кеші лаунчерів
- **Проблема:** Vortex, MO2 та CurseForge зберігають оригінальні завантажені архіви `.zip`/`.7z` після їх розпакування. Лаунчери (Steam, Epic, Ubisoft, EA) тримають гігабайти Chromium/CEF кешу.
- **Рішення:** 
  1. Зачистка безпечного веб-кешу лаунчерів (який повністю регенерується за потреби).
  2. Пошук та пропозиція очищення завантажувальних дублікатів мод-менеджерів.

### 3.6. GT-186: [Імплементація] Core Engine & Manifest Rules у crates/core
- Розширення `crates/core/src/rules.rs`, додавання `workshop.rs`, `staging.rs`, `saves.rs`.
- Оновлення `rules.json` новими патернами для UE/Unity/WER дампів.

### 3.7. GT-187: [Імплементація] UI/UX нових категорій та Save/Workshop UI
- Інтеграція нових категорій у дерево знахідок `crates/app`.
- Візуальні бейджі безпеки (Safety Badges ⚠).
- Окреме модальне вікно / таб для **Smart Save Pruner** із повзунком кількості сейвів та кнопкою створення бекапу.
